# 实施计划

> 本文档是 Frontend → Swift 原生化迁移的执行路线图，定义阶段目标、批次划分、验收标准、Agent 分工和依赖关系。
>
> 产品前提已确认：本计划交付的是 **macOS 专用客户端**，不是浏览器端 Web 替换。Nuxt 前端用于提炼功能与交互基线；Swift App 通过可配置的 backend base URL 连接现有后端。
>
> 本版已与 [04-迁移执行清单](./04-%E8%BF%81%E7%A7%BB%E6%89%A7%E8%A1%8C%E6%B8%85%E5%8D%95.md) 对齐：这里负责“路线图 + 批次设计 + 验收标准”，不承担勾选进度记录。

---

## 1. 总体路线图

```text
Week 1   ─ Phase 1: 基础设施收尾
Week 2   ─ Phase 2: 核心页面壳层 + 最小数据流
Week 3-4 ─ Phase 3: 工作台深化 + 原生增强
Week 5   ─ Phase 4: 联调打磨 + 发布准备
```

**总工期：5 周**

### 1.1 执行原则

- 以“单次批次可在 `128k` 上下文内闭环完成”为第一约束
- 默认一次只推进 `1` 个批次，不跨多个页面、不跨多个 Agent
- 路线图保留父任务视角，但实际落地必须使用批次粒度
- 批次之间允许并行，但尽量避免同时修改同一 `ViewModel` 或同一页面根视图

### 1.2 单次批次边界

- 单次读文件建议：
  - 目标 Swift 文件 `<= 8`
  - Nuxt 参考页面 `<= 3`
  - 本文档只阅读当前批次相关小节
- 单次写文件建议：`<= 4`
- 单次 diff 建议：`150~350` 行
- 一旦某步包含“页面骨架 + 弹窗表单 + 业务动作 + 状态修正”，必须继续拆分

## 2. Phase 1 — 基础设施收尾（第 1 周）

> 现状：`A1-A20`、`B1-B16` 主体已完成；本阶段剩余工作集中在联调、测试、文档化。

### 2.1 Agent A：基础框架 + 数据模型 + API 层

#### 父任务 A21：与后端联调

**目标**：确认 Swift 客户端和现有 backend 在真实环境下可闭环交互。

**执行批次**:

| 批次 | 目标 | 读写范围建议 |
|---|---|---|
| A21.1 | 启动 backend，校验 base URL、连接配置读写、基础列表接口可达 | `ConnectionSettingsStore`、`APIClient`、最小启动入口 |
| A21.2 | 烟测 Drama / Episode 主 CRUD：列表、详情、创建、删除、导航主链路 | `APIEndpoints` 中 drama/episode 相关、对应最小 UI 入口 |
| A21.3 | 烟测 Settings / Studio 关键端点：AI 配置、Agent 配置、Skill、剧本步骤主动作 | `APIEndpoints` 中 ai/agent/skill/studio 相关 |

**验收标准**:

- Swift App 能读取并持久化 backend base URL
- `GET /api/v1/dramas` 可成功请求并解析
- Drama / Episode 主链路真实可用
- 设置页与工作台关键 API 至少完成一次真实调用验证
- 联调发现的字段偏差被记录并修正

#### 父任务 A22：API 层单元测试

**目标**：让 API 底座具备可回归的最小测试保护。

**执行批次**:

| 批次 | 目标 | 读写范围建议 |
|---|---|---|
| A22.1 | 补 `Drama / Episode / Storyboard / AIServiceConfig` 解码测试 | `ModelDecodingTests.swift` |
| A22.2 | 补 `APIClient` 的 GET / POST / DELETE 成功与失败用例 | `APIClientTests.swift` |
| A22.3 | 补 `PollingCoordinator / DownloadExportService` 的最小行为测试 | 对应 service tests |

**验收标准**:

- 关键模型具备解码测试
- `APIClient` 覆盖至少 3 类基础请求路径
- 轮询与下载的关键分支具备最小行为测试

#### 父任务 A23：导出接口文档

**目标**：让 Phase 2/3 的实现不再反复反查 API 层细节。

**执行批次**:

| 批次 | 目标 | 交付物 |
|---|---|---|
| A23.1 | 整理 `APIEndpoints` 清单，按模块列出方法 | API 概览文档 |
| A23.2 | 补请求示例、错误处理约定、轮询与下载说明 | 调用约定文档 |

**验收标准**:

- 其他 Agent 能直接按文档调用 `APIEndpoints.*`
- 文档覆盖 drama / episode / ai config / agent / skill / storyboard / generation / export 主模块
- 轮询与下载行为有清晰说明

### 7.1 分支建议

- 一个父任务可对应一个长期分支
- 一个执行批次尽量对应一次独立提交
- 若批次之间互相冲突，优先拆分目录所有权，而不是在一个分支里硬做多个批次

### 7.2 合并规则

- Phase 内各 Agent 分支独立开发
- 每个父任务完成后再合并
- 合并前必须满足该父任务的最终验收标准

## 8. 风险预案

| 风险 | 触发条件 | 预案 |
|---|---|---|
| 单次任务仍然过大 | 某批次预计修改 `> 4` 文件或 diff `> 500` 行 | 再拆一级，例如 `E10.3a / E10.3b` |
| SwiftUI `SearchablePicker` 细节过重 | 页面批次被组件问题拖住 | 回退到已完成组件的最小用法，不在页面批次里扩组件 |
| Grid 工具交互复杂 | `G2` UI 超出单次上下文承载 | 先完成状态机与分配表格，叠加预览后置 |
| 后端字段与推断不一致 | 联调解析失败 | 在 `A21` 中先修 `CodingKeys`，不要把修复分散到页面批次 |
| Phase 2 冲突严重 | C/D/E 同时改共享文件 | 提前固定路由、导航、共享组件边界 |
