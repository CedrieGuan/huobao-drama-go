## 2. 128k 上下文执行约束

### 2.1 单次执行边界

- 单次只做 `1` 个执行批次；不要跨 Agent，不要同时推进两个页面
- 单次参考材料上限：
  - 本文档中对应批次所在小节
  - `03-实施计划` 对应功能验收小节
  - 目标 Swift 文件 `<= 8` 个
  - 对应 Nuxt/Vue 参考文件 `<= 3` 个
- 单次写入文件上限：`<= 4` 个
- 单次代码 diff 建议：`150~350` 行；若预计 `> 500` 行，必须再拆
- 单次验证上限：只做与该批次直接相关的最小验证，不做全量回归

### 2.2 强制拆分信号

- 同时改 `ViewModel + 3 个以上 View`：必须拆
- 同时覆盖“页面骨架 + 业务动作 + 弹窗表单”：必须拆
- 同时理解“设置页 + 工作台 + API 端点修复”：必须拆
- 某一步需要同时读取 `> 2` 个前端页面作为参考：必须拆
- 单次执行需要引入新的共享组件时，只能先做共享组件批次，再做消费方批次

### 2.3 批次完成定义

- 代码已落到仓库
- 完成该批次对应的最小验证
- 本文档勾选该批次
- 若影响父任务进度，同步更新阶段数量和里程碑状态
